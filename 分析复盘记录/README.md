# 预测记录、智慧复盘与习惯塑形

执行[项目规程](../AGENTS.md)，经验写入[总复盘总结](总复盘总结.md)，方法回查[论文索引](../温故而知新学习资料/README.md#review-papers)。历史战报保留原样，其中的门槛、机构意图和事后归因均需重新核验。

## 赛前封存

每个比赛日用`YYYY-MM-DD_预测.md`，文首JSON；记录实际写入时间，不强制固定钟点或补造开赛前两小时封存。没有可靠封存证据就注明。
卡片保留既有字段，并为新比赛记录以下信息（null表示尚缺数据，不是零概率；示例不可用于真实结算）：

```json
{
  "日期": "YYYY-MM-DD",
  "类型": "赛前预测",
  "记录时间": null,
  "数据截止时间": null,
  "模型版本": null,
  "逐场预测": [{
    "比赛ID": null, "场次": null, "开球时间": null,
    "市场类型": "had", "让球数": null, "结算范围": "常规时间含补时",
    "模型胜平负概率": null, "市场胜平负概率": null,
    "赔率": null, "赔率来源与时间": null, "概率方法": null,
    "推荐排名": null, "决定": "待评估", "理由": null,
    "关键缺失": [], "反例与替代解释": []
  }]
}
```

概率顺序固定为主胜、平、客胜，有限且在0到1之间、总和为1；市场和模型分列，不用经验加分伪造概率。候选、未选与观察场次均保留。
记录赛前更新的实际时间和版本，赛后禁止回填为原预测。没有同一结算市场的可成交赔率时不计算EV或收益。

## 赛后先审过程，再揭示结果

1. 冻结原预测，先检查当时可得信息是否遗漏、计算是否正确、是否只寻找支持解释。
2. 核验比分来源及常规时间结算。加时/点球结束与常规比分分开；未完场、取消或缺比分不计作输赢。
3. 核对所有原候选与未选样本；未选打平只是需检查样本，不能凭赛果认定误杀；入选打平也不证明理由正确。
4. 区分可修复数据错误、推理缺口、待检验概率失准及随机波动。机制解释需要可区分的额外证据，允许原因未明。
5. 只保留值得复用的一个或少数检查动作；新旧方法在后续冻结样本比较，记录反例与撤回条件，不要求每场修改阈值。

每日用`YYYY-MM-DD_复盘.md`并保留既有聚合卡片兼容字段：

```json
{
  "日期": "YYYY-MM-DD", "星期": "周X", "类型": "赛后复盘",
  "开售总场次": 0, "实际平局场次": [],
  "推演战绩": {"主推场次": 0, "平局命中": 0, "1-1波胆比分命中": 0},
  "逐场赛果": [],
  "经验候选": [{
    "触发情境": null, "检查动作": null, "证据与反例": [],
    "暂定调整": "不改规则", "验证方案": null,
    "后续反馈": null, "失效条件": null, "状态": "待验证"
  }]
}
```

示例中的0仅表示确实没有该类场次；未知用null并等待核查，不得为了生成看板补成0。实际平局列表应覆盖统计范围全场，另保存比分来源与统一结算口径。
`逐场赛果`应记录比赛ID、市场、常规比分、完场状态和来源；现有对账机仅汇总聚合字段，**尚未自动关联逐场预测、概率评分、排名或收益**。

## 评估与经验升级

先确定比较对象、联赛/主客场等有依据的分层、损失指标与时间窗口；分组不能按结果反复试到好看。
完整概率可比较Brier、log loss及校准；序贯观察需相应有效方法，普通置信区间不能冒充随时有效置信序列。CORP二元校准不能直接认证完整三分类联合校准。
命中率、校准与收益分开；市场基准使用同场、同时间、同结算范围。记录成本和不确定性，样本不足则维持假设。
论文指导方法，不提供本项目通用的0.8失球线、60%对抗线、固定加5%或75分门槛。

## 程序职责与证据保存

[对账机](../脚本/对账机.py)校验非负计数与相互约束，再原子更新[看板](总准确率.md)；格式或计数错误保留原看板等待核查。历史卡片汇总不是独立赛果认证。
头号推荐不能从场次编号、emoji或赛后叙述猜出；数据不够则不统计。测试在临时目录验证正常、失败与空样本，不要求任何胜率下限。
[Graphify](../graphify-out/graph.html)用于寻找相关资料；文献引用、相似场景和因果证据是不同关系。停止为了零孤岛强行连边，保留来源与已取代标记。
[整改依据与验证边界](#rule-audit)记录本次变化与未验证边界。长期经验可引用证据文件，不能以“防流水账”为由禁止溯源；主体仍围绕可复用行动。

## 整改依据与验证边界

审计日期：2026-09-14。执行[现行规程](../AGENTS.md)，经验入口为[习惯塑形](总复盘总结.md)。

范围：检索项目规程、全部业务与测试脚本、历史预测/复盘、论文Markdown及图谱；沿采集→领域→用例→SQLite→CLI及复盘→看板追踪调用。不是对每篇论文、每场历史数据的独立事实认证。原PDF和每日战报保留原样。

| 问题与原位置 | 修复后的行为 | 保留的边界 |
| --- | --- | --- |
| AGENTS、README及总复盘把庄家必赚、停售内幕当公理 | 区分事实、关联与机制假设，完整比较胜平负 | 不能用赛果单独反推操盘 |
| 0.8失球、60%对抗率及热门低赔率直接准入/否决 | 七类条件复核，旧资格函数返回未决与待查信息 | None不是反向否决，也不是批准；无自动推荐 |
| 固定75/85评分、特定阵容扣15分、技能固定加百分比 | 停止直接应用未验证的评分/修正，市场与独立模型分列 | 项目内约束外部技能的使用，未改全局安装文件 |
| 赔率变化直接输出“诱平”“实防” | 输出实际方向、变动量和原因待核验 | 提醒阈值可调，仅控制提醒 |
| had缺失时hhad赔率混入普通平项 | 快照与SQLite保留市场及让球线；CLI明确平项隐含概率 | 让球平不等于常规平局，旧原赔率不改 |
| 相同场次代码跨周、切市场被拼成连续变盘 | 限定比赛ID、市场和让球线，时间必须递增 | 默认轨迹只取最新同名比赛，旧数据留在账本 |
| 微观接口缺失时补休赛7/5天、零xG或零平局率 | 保留未知；采样赛程晚于目标日期时拒绝作为赛前依据 | 不声称自动找到了正确历史赛程 |
| 加时/点球完场使用总进球结算常规胜平负 | 常规比分与完场状态分开，缺失则不可结算 | 需同时检查settlement_ready |
| 对账用特定编号和emoji猜头号推荐，测试要求胜率≥25% | 无统一排名则不统计；接受零胜率和空样本 | 仅卡片计数汇总，不认证历史真假 |
| 旧卡片字段不同被漏算实际平局 | 兼容明确字段别名并校验计数关系，错误不覆盖看板 | 缺失值不是零；不补造历史完整概率 |
| 总结禁止引用证据、每次复盘固化新红线 | 用具体检查动作与反馈塑造习惯，允许不改规则与撤回 | 证据可追溯，单场不升级普遍规律 |
| 图谱脚本批量造关系并强行连通 | 旧入口改为只读，文档按真实内容重新提取 | 图边不是因果证据，旧无来源推断需标为待核查 |
| 项目Shin笔记公式漏项并把z当黑幕测量 | 对照公开实现修正q平方除以倒数总和，撤回错误求解器和示例 | 领域程序仍为比例归一化，未新增Shin实现 |
| 宣称自动封盘、自动训练和胜率逼近100% | 如实区分已记录、已执行、尚未实现及未验证 | 后续预测效果必须用冻结的未来样本评价 |

方法依据：[Macrì-Demartino等的动态信息借用](https://arxiv.org/abs/2508.05891v1)、[Giacomini与White的条件预测检验](https://doi.org/10.1111/j.1468-0262.2006.00718.x)、[Choe与Ramdas的序贯比较](https://arxiv.org/abs/2110.00115v6)、[Dimitriadis等的CORP](https://doi.org/10.1073/pnas.2016191118)。本次采用它们对情境、评估与不确定性的启发，没有把修改后的启发式包装为论文模型的实现。

验证：回归例覆盖旧阈值两侧、缺失数据、不同市场/比赛、赔率非法值、常规比分与加时比分、SQLite回读、失败与空样本计数；完整测试另检查现有采集/用例行为。测试只使用模拟接口与临时数据库。

尚未完成的能力：历史逐场预测与来源核验、自动Brier/log loss与CORP、置信序列、新旧方案前瞻比较和真实成交收益统计。规程已经要求记录所需字段，但不能宣称这些统计方法已运行或预测胜率已提高。
