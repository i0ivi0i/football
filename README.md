# 足球倍率精算与赛事量化预测系统 (Football Quant & Odds Actuarial System)

> **定位**：基于“数据为王 + 庄家倍率精算”的足球赛事量化分析与预测工作区。专攻中国体育彩票平局博弈，与庄共舞。

---

## 1. 核心架构与系统规范

### 1.1 系统架构设计
* **后端架构**：10/10 纯正洋葱整洁架构（Domain-Driven Design, DDD），信达雅纯中文命名。
* **分层边界**：
  * `脚本/领域/`：纯净 Python 领域模型（实体、值对象、核心精算逻辑），零外部依赖；
  * `脚本/应用/`：业务用例编排（心电图探测用例、轨迹回溯用例），无数据库/网络细节；
  * `脚本/适配器/`：端口实现（体彩官方网关适配器、本地 SQLite 时序仓储）；
  * `脚本/心电图录像机.py`：组装根（Composition Root）与 CLI 入口。

### 1.2 数据管道规范
* **官方赔率直连管道（体彩直连）**：
  * 免密端点：`https://webapi.sporttery.cn/gateway/uniform/football/getMatchCalculatorV1.qry?channel=c`
  * 涵盖：胜平负(`had`)、让球(`hhad`)、总进球(`ttg`)、比分(`crs`)、半全场(`hafu`)。
  * 时效性：秒级时间戳抓取与 SQLite 时序沉淀 (`脚本/数据/赔率心电图.db`)。
* **全球微观数据管道（API-Sports）**：
  * 端点：`https://v3.football.api-sports.io/`
  * 双 Key 自动轮换：`832130dcfdadb0aac6af9e19300f74ec` / `d3ee3cb753c07c442d7d3fd16bb6dceb` (100次/天)。
  * 产出：次级联赛数据、关键球员画像（门将扑救率、中卫对抗胜率、战术犯规率）。
* **全球四大机构基准对账**：
  * 强制双向拉取：Pinnacle（平博）、Bet365、William Hill（威廉希尔）、Betfair（必发）。

## 3. 硬性运行规则与操作契约

1. **时钟锚点铁律**：凡涉及“昨天、今天、明天”，严禁凭记忆臆断，必须首先核验宿主机硬件时钟（`datetime.now()`）。
2. **TDD 铁律**：所有代码变更必须严格遵守测试驱动开发（红-绿-重构），测试必须 100% 通过（`pytest 脚本/测试 -v`）。
3. **零残留与极简主义**：严禁产生无用临时脚本，运行完毕立即清理；依赖优先使用标准库。
4. **Graphify 零孤岛契约**：
   * 所有建图强制使用官方 CLI `/c/Users/home/.local/bin/graphify.exe`，模式必须带 `--mode deep`。
   * 新建文档或模块必须包含显式双向链接，全局连通分量必须严格保持为 1（全网大一统）。
   * 必须启用 Git 自动钩子（`graphify hook install`），代码提交自动更新图谱。
5. **JSON 卡片契约**：每日推演与复盘报告文首必须内嵌结构化 ````json``` 代码块，供 [对账机](脚本/对账机.py) 秒读。
